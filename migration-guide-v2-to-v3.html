DataFlow v2→v3 Migration Guide

Updated: October 2024 | Duration: 30-60 minutes

📋 Quick Facts:
• Migration deadline: October 15, 2024
• Estimated time: 30-60 minutes (varies by pipeline complexity)
• Rollback available: Yes (within 7 days)
• Support available: Yes (24-hour response)
---

Before You Start

Prerequisites

  • ✅ DataFlow v2.5 or later (check: dataflow --version)
  • ✅ Access to production and staging environments
  • ✅ 1-2 hours of focused time (no interruptions)
  • ✅ Recent backup of your pipeline definitions
⏰ Timing Recommendation: Plan migration during off-peak hours. Running pipelines will complete before the upgrade. Typical completion time: 2-4 hours depending on your infrastructure.
---

Migration Timeline

Phase 1: Preparation (5 min) — Check prerequisites
Phase 2: Staging (20-30 min) — Test migration in safe environment
Phase 3: Production (10-20 min) — Run migration on live pipelines
Phase 4: Validation (10 min) — Verify everything works
---

Phase 1: Preparation (5 minutes)

1

Upgrade DataFlow CLI

Ensure you have the latest version with migration tools:

curl -fsSL https://install.dataflow.io | sh
dataflow --version  # Should be 3.0.0 or later
👤 Non-technical users: Ask your DevOps/data engineer to run this command. Takes 2 minutes.
2

Export Current Pipelines

Create a backup of all your pipeline definitions:

dataflow export --output backup-v2.json

This creates a timestamped backup file. Keep this safe (you can restore if needed).

---

Phase 2: Staging (20-30 minutes)

3

Run Auto-Migration in Staging

Test the automated migration in your staging environment first:

dataflow migrate --environment staging --from v2 --to v3 --dry-run

The --dry-run flag shows what will change without applying changes. Review the output.

Expected output: A report showing which pipelines will be modified and what changes. Example:

✓ customer_sync: 3 steps (3 syntax changes)
✓ data_validation: 1 step (1 config change)
→ Ready to migrate 2 pipelines

If you see errors: See Troubleshooting section

4

Apply Migration to Staging

Now run the actual migration (without --dry-run):

dataflow migrate --environment staging --from v2 --to v3

This converts your pipeline definitions to v3 format. Takes 2-5 minutes.

5

Test Pipelines in Staging

Run your most critical pipelines in staging:

dataflow execute --pipeline customer_sync --environment staging

For non-technical users: Your data team should run at least 3-5 of your most important pipelines and verify the output matches what you expect.

Troubleshooting: If tests fail, see Troubleshooting section. Most issues are simple YAML fixes.
---

Phase 3: Production (10-20 minutes)

6

Schedule Maintenance Window

Choose a low-traffic time to upgrade production. Migration requires a brief pause in pipeline execution.

Downtime estimate: 5-15 minutes (depends on number of pipelines)

Recommended timing: Off-peak hours, weekday early morning, or weekend

For business users: Notify stakeholders that DataFlow will be briefly unavailable. Any scheduled jobs will resume automatically after migration.
7

Stop Active Pipelines

Wait for running jobs to complete, then pause new executions:

dataflow stop --all-running

Waits for jobs to finish gracefully (can take 10-30 min depending on workloads). Safe—no data loss.

Status check: dataflow status shows when all jobs are idle
8

Run Production Migration

Execute the migration:

dataflow migrate --environment production --from v2 --to v3

Converts all production pipelines. Typical time: 5-15 minutes.

Success message: ✓ Migration complete. 24 pipelines converted. Ready for v3.0
---

Phase 4: Validation (10 minutes)

9

Verify Production Pipelines

Run your most critical pipelines:

dataflow execute --pipeline customer_sync --environment production

Verify:

10

Resume Normal Operations

If all tests pass:

dataflow resume --all

Your production pipelines resume their normal schedule. You're done! 🎉

Rollback if needed: If something goes wrong, you have 7 days to rollback:
dataflow rollback --from v3 --to v2 --backup backup-v2.json
---

Troubleshooting

Error: "YAML syntax error after migration"

Cause: Custom transformation logic uses old function names

Solution: Replace old function names with new ones. See v3.0 Release Notes for new function names.

Error: "Schema validation failed"

Cause: Source or destination system no longer exists or permissions changed

Solution: Verify database/API credentials are still valid. Test connection in DataFlow UI.

Pipeline runs slower in v3.0

Cause: Default parallelism setting changed

Solution: Add parallelism: 16 to your pipeline config to re-enable parallel execution.

Webhook events not delivering

Cause: Event schema changed slightly in v3.0

Solution: Review webhook event payload format in Webhooks API Reference. Update your webhook receiver if needed.

What Changed for Your Team

If you run pipelines: Everything looks the same in the UI. Performance is actually better (+40% faster on average).

If you integrate via API: v2 API is retired. Update your applications to use v2.5 API or newer.
