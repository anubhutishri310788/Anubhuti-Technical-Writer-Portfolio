DataFlow Webhooks API Reference

API Version: v2.5+ | Last Updated: October 2024

What are webhooks? Receive real-time notifications about pipeline events (success, failure, completion) delivered to your infrastructure. No polling required.
---

Authentication

All webhook requests require an API key in the Authorization header:

Authorization: Bearer sk_live_YOUR_API_KEY

How to generate an API key:

  1. Log in to DataFlow dashboard
  2. Go to Settings → API Keys
  3. Click "Generate Key"
  4. Copy and store securely (never commit to version control)

Security best practices:

  • Rotate API keys every 90 days
  • Use separate keys for production and staging
  • Revoke keys immediately if compromised
  • Never log or display API keys in error messages

Webhooks

Register a Webhook

POST /v2/webhooks

Subscribe to pipeline events. Choose which events trigger your webhook.

Request

POST https://api.dataflow.io/v2/webhooks
Authorization: Bearer sk_live_YOUR_API_KEY
Content-Type: application/json

{
  "url": "https://yourapp.com/webhooks/dataflow",
  "events": ["pipeline.completed", "pipeline.failed"],
  "description": "Production alerts webhook"
}

Request Body Parameters

Field Type Required Description
url string Yes HTTPS endpoint where events will be delivered. Must be publicly accessible.
events array Yes List of events to subscribe to. See Webhook Events section.
description string No Human-readable name for your webhook (e.g., "Slack alerts", "Email notifications")
active boolean No Default: true. Set to false to temporarily disable without deleting.

Response (201 Created)

{
  "id": "wh_live_abcd1234efgh5678",
  "url": "https://yourapp.com/webhooks/dataflow",
  "events": ["pipeline.completed", "pipeline.failed"],
  "description": "Production alerts webhook",
  "active": true,
  "created_at": "2024-10-01T14:30:00Z",
  "secret": "whsec_live_xyz123"
}

⚠️ Important: Store the secret value securely. Use it to verify webhook signatures (see Webhook Verification).

Webhook Events

Supported Events

Event Trigger Payload Includes
pipeline.created New pipeline defined Pipeline ID, name, version
pipeline.started Pipeline execution begins Pipeline ID, execution ID, start time
pipeline.completed Pipeline finished successfully Pipeline ID, execution ID, duration, row counts
pipeline.failed Pipeline errored Pipeline ID, execution ID, error message, step number
job.warning Non-critical issue detected Pipeline ID, warning message, affected rows

Webhook Event Payload

Example: pipeline.completed Event

{
  "id": "evt_live_xyz789",
  "type": "pipeline.completed",
  "timestamp": "2024-10-01T14:35:22Z",
  "attempt": 1,
  "data": {
    "pipeline_id": "pipe_live_abc123",
    "pipeline_name": "customer_sync",
    "execution_id": "exec_live_def456",
    "status": "succeeded",
    "duration_seconds": 127,
    "rows_read": 5432,
    "rows_written": 5401,
    "rows_skipped": 31,
    "started_at": "2024-10-01T14:33:15Z",
    "completed_at": "2024-10-01T14:35:22Z"
  }
}

Event Payload Schema

id (string) — Unique event ID. Use to deduplicate if you receive duplicates.
type (string) — Event type (e.g., "pipeline.completed")
timestamp (ISO 8601) — When the event occurred
attempt (integer) — Delivery attempt (1-5). Indicates retries.
data (object) — Event-specific details (structure varies by event type)

Webhook Verification

Verify webhook signatures to ensure events come from DataFlow (not malicious sources).

Verification Steps

  1. Retrieve the X-DataFlow-Signature header from the request
  2. Combine timestamp (from payload) + webhook secret
  3. Compute HMAC-SHA256 hash
  4. Compare with signature header

Python Example

import hmac
import hashlib
import json

def verify_webhook(request_body, signature_header, webhook_secret):
    """Verify DataFlow webhook signature"""
    
    # Parse JSON payload
    payload = json.loads(request_body)
    timestamp = payload['timestamp']
    
    # Create signed message
    signed_content = f"{timestamp}.{request_body}"
    
    # Compute HMAC-SHA256
    expected_signature = hmac.new(
        webhook_secret.encode(),
        signed_content.encode(),
        hashlib.sha256
    ).hexdigest()
    
    # Verify match
    return hmac.compare_digest(
        signature_header,
        f"sha256={expected_signature}"
    )

# Usage
is_valid = verify_webhook(
    request_body='{"type":"pipeline.completed",...}',
    signature_header='sha256=abc123...',
    webhook_secret='whsec_live_xyz123'
)

Retry Logic & Delivery Guarantees

DataFlow retries failed deliveries automatically:

Attempt Delay Triggers On
1 Immediate Event occurs
2 5 seconds Timeout, 5xx error, or connection failure
3 1 minute Same failure conditions
4 10 minutes Same failure conditions
5 1 hour Final attempt before giving up

Your endpoint must:

  • Return 200 OK within 30 seconds
  • Accept POST requests with JSON body
  • Be publicly accessible (HTTPS only)
  • Handle duplicate events (same id) gracefully

Error Handling

HTTP Status Codes

Status Meaning What to Do
400 Bad Request Check your request body for syntax errors
401 Unauthorized Verify API key is valid and included in header
404 Not Found Webhook doesn't exist or already deleted
429 Rate Limited Wait before retrying (limit: 100 requests/minute)
500 Server Error Retry later. Check status.dataflow.io for incidents.

Error Response Example

{
  "error": {
    "code": "invalid_event_type",
    "message": "Event type 'pipeline.unknown' is not supported",
    "details": {
      "valid_events": [
        "pipeline.created",
        "pipeline.completed",
        "pipeline.failed"
      ]
    }
  }
}

Troubleshooting

Webhooks not delivering

Check: Is your endpoint HTTPS? Is it publicly accessible? Try accessing it from a browser. Verify API key is valid.

Receiving duplicate events

Solution: Store processed event IDs and skip duplicates. DataFlow may retry if your endpoint times out or returns an error.

Signature verification failing

Check: Are you using the correct webhook secret? Is your timestamp parsing accurate? Review Python example above.

Rate Limits

  • API requests: 100 per minute per API key
  • Webhook deliveries: No limit (events deliver as they occur)
  • Webhooks per account: 50 maximum

Contact support if you need higher limits.
